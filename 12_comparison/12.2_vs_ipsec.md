## 12.2 MACsec vs IPsec

MACsec 与 IPsec 是最常被拿来比较的一对——都是"网络层附近的逐包保护"，都源自 IEEE/IETF 的成熟标准体系，但它们对"保护范围"的回答截然不同。

### 12.2.1 逐项对照

| | MACsec | IPsec |
|---|---|---|
| 通道标识 | SCI | SPI |
| 控制面认证 | AES-CMAC(ICK) | IKE AUTH（签名/PSK） |
| "PSK" 的含义 | 预共享 **CAK+CKN**；SAK 仍由 KS 生成分发 | 预共享 IKE 认证凭据；ESP 密钥仍由 IKE 派生 |
| 数据面密钥 | SAK（KS 随机生成，**不是** KDF(CAK)） | ESP 密钥从 IKE keymat 派生 |
| 换钥触发 | PN 耗尽（32 位很快）或策略 | 生命周期/流量计数策略 |
| 范围 | 单跳（下一台 SecY 解开） | 端到端或跨 WAN 隧道 |

### 12.2.2 关键差异一句话

**MACsec 保护"链路"，IPsec 保护"路径"。** MACsec 帧过路由器就解开了；IPsec 包穿过多少路由器都密着。

由此派生出几条实践推论：

- **拓扑假设不同**：MACsec 要求两端在同一个以太网段（直连或经二层交换网）；IPsec 只要求 IP 可达。
- **"PSK"语义形似而神不同**：两者预共享的都只是"根材料"，数据面密钥都另有一套派生/分发（MACsec 是 KS 生成 + KEK 封装分发，见[第二章](../02_key_hierarchy/README.md)；IPsec 是 IKE keymat 派生）。但 MACsec 的 SAK 由 Key Server **随机生成**而非 KDF 派生——这一点常被误解（[2.2 节](../02_key_hierarchy/2.2_generation.md)）。
- **换钥压力不同**：32 位 PN 在高速链路上几十秒烧完（[6.1 节](../06_lifecycle/6.1_why_rekey.md)），所以 MACsec 的 rekey 是常态事件；IPsec 的 SA 生命周期通常以分钟/小时计。
- **抓包对照**：两套实验室各有一份"完整会话"抓包——本仓库的 `session-full.pcap`（MKA + 0x88E5）与 ipsec-study-guide 的 IKEv2 + ESP；把两份放在一起看握手与数据面的分工，比读十遍文档都直观。
