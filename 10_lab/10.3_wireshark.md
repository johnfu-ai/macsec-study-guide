## 10.3 Wireshark：验 ICV、解 SAK

Wireshark 自带 `mka` 与 `macsec` 两个解析器，配合 `captures/keys.json` 里的演示密钥，可以做到教科书级的三件事：过滤出协议帧、校验 MKA ICV、从 MKPDU 里解封 SAK。这一节是操作速查。

### 10.3.1 显示过滤器速查

```
mka || macsec
eapol.type == 5
eap.code == 3
eth.type == 0x88e5
macsec.sl || macsec.an
mka.param_set_type == 4     # Distributed SAK
mka.delay_protect == 1      # delay protect stories
```

逐条含义与更多常用过滤器：

| 过滤器 | 显示什么 |
|---|---|
| `mka` | EAPOL-MKA |
| `macsec` | EtherType 0x88E5 |
| `eapol.type == 5` | MKA packet type（Type 6 是 EAPOL-Announcement，不是 MKA） |
| `eap.code == 3` | EAP-Success（EAP 路线的起点） |
| `eth.type == 0x88e5` | MACsec |
| `mka.key_server` | Key Server 标志位 |
| `mka.cak_name` | CKN |
| `mka.param_set_type == 4` | Distributed SAK 参数集（换钥时分发新 SAK） |
| `mka.delay_protect == 1` | Delay Protect 故事线 |
| `macsec.sl` | Short Length |
| `macsec.an` | Association Number |

### 10.3.2 让 Wireshark 验 ICV、解 SAK

默认情况下，Wireshark 能解析 MKA 与 MACsec 的字段结构，但 MKA ICV 校验与 SAK 解封需要 CAK。配置路径：

```
Preferences → Protocols → MKA → CKN 表
```

把 `captures/keys.json` 里的 CKN 与 CAK 成对填入。此后 Wireshark 就能：

- 用 ICK 逐帧校验 MKA ICV（[4.6 节](../04_mka/4.6_parameter_sets.md)的 ICV 参数集不再是"裸字节"）；
- 从 Distributed SAK 参数集里用 KEK 解开 AES-KeyWrap，拿到明文 SAK；
- 用 SAK 解开 `0x88E5` 数据面帧，直接看到内层 IPv4。

这正是第二章密钥体系的一次全流程演练：CAK → KEK/ICK → SAK → GCM，每一跳都发生在你眼前。

### 10.3.3 Windows 下打开 WSL 文件

抓包在 WSL2 里生成、Wireshark 装在 Windows 侧时，用 UNC 路径直接打开：

```
\\wsl$\Ubuntu\home\<you>\macsec-study-guide\captures\session-full.pcap
```

把 `<you>` 换成你的用户名、`Ubuntu` 换成发行版名即可；性能敏感时也可以先把 pcap 复制到 Windows 本地再打开。
