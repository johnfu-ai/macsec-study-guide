## 10.4 Live 实验：netns 与 veth

参考抓包是"录好的证据"，live 实验则是"现场重演"：脚本用两个网络命名空间 + veth + 网桥搭出一条虚拟链路，以 AF_PACKET 把参考帧真的打到线上，再用 tcpdump 抓一份 `captures/live-session.pcap` 回来。全程不需要内核 MACsec 模块。

### 10.4.1 运行

```bash
sudo make lab    # 搭建 netns/网桥，回放参考帧，写出 captures/live-session.pcap
sudo make down   # 实验后清理 netns 与网桥
```

想在实验进行时实时观察线上的 EAPOL/MACsec：

```bash
sudo tcpdump -i br-macsec -nn 'ether proto 0x888e or ether proto 0x88e5'
```

抓回来的 `live-session.pcap` 与参考抓包逐字节一致——因为它本来就是同一批帧，只是这回真的从一块（虚拟）网卡上过了一遍。

### 10.4.2 网桥为什么默认丢 MKA

Linux 网桥默认**不转发** PAE 组播目的地址 `01:80:c2:00:00:03`——这是 802.1D 对保留组播地址的保守处理，也是新手在网桥拓扑里抓不到 EAPOL/MKA 的头号原因。解决办法是把 `group_fwd_mask` 的对应位置 1：

```bash
echo 8 | sudo tee /sys/class/net/br-macsec/bridge/group_fwd_mask
```

实验室脚本（`sudo make lab`）已经自动写好这一位（与 ieee-802.1x-study-guide 的做法相同）。如果你手工重建了网桥，需要重新设置；仍抓不到时按 10.5 节排障。

### 10.4.3 如果内核真的有 CONFIG_MACSEC

本实验室的写作环境（WSL2）内核未开启 `CONFIG_MACSEC`，所以数据面帧由 Python 组包、AF_PACKET 回放，而非内核 SecY 卸载。若你的内核打开了该选项：

- 可以用 `ip link add ... type macsec` 创建**真实 SecY**，让内核完成保护/验证（配置路径见[11.1 节](../11_deployments/11.1_linux.md)）；
- 本仓库的解析器同样能读那种 pcap——只需要你提供对应的 SAK。
