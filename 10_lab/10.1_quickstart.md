## 10.1 快速开始：test / generate / verify

整个实验室只有一个 Python 依赖（`cryptography`），不需要内核 MACsec 模块，也不需要 root（live 实验除外）。三条 make 命令就能把"测试—生成—验证"的闭环跑通，这一节给出最小路径。

### 10.1.1 环境准备

```bash
cd ~/macsec-study-guide
python3 -m pip install -r requirements.txt   # cryptography
make doctor   # 可选：检查 python3+cryptography / tshark / tcpdump 是否就绪
```

`make doctor` 会分别报告三项依赖：Python 与 `cryptography` 是必需的；`tshark` 只影响 `make verify` 的协议识别检查；`tcpdump` 只在 10.4 节的 live 实验里用到。

### 10.1.2 三条命令

```bash
make test        # IEEE 向量 + 往返加解密 / ICV / SAK unwrap（35 项）
make generate    # 写出 captures/*.pcap 和 captures/decoded/*.md
make verify      # 测试 + tshark 能否认出 mka / macsec（15 项）
```

- `make test` 是密码学的"裁判"：IEEE 公开 GCM 测试向量逐字节比对，任何实现偏差都会在这里暴露；
- `make generate` 产出 15 个参考抓包与配套的字段级报告（详见 10.2 节与附录 D）；
- `make verify` 在测试之上叠加 tshark 检查——确认生成的 pcap 能被真实的 Wireshark 解析器认出 `mka` 与 `macsec`。

已经生成过抓包、只想用 tshark 快速过一眼的话，不需要 sudo：

```bash
tshark -r ../captures/session-full.pcap -nn
tshark -r ../captures/mka-handshake.pcap -Y mka -V | less
tshark -r ../captures/macsec-lab-encrypted.pcap -Y macsec -V | less
```

### 10.1.3 打开第一个抓包

用 Wireshark 打开 `captures/session-full.pcap`，输入显示过滤：

```
mka || macsec
```

你会看到一条完整的 PSK 故事线：MKA 握手六帧（选 Key Server、分发 SAK、双方 SAK Use）之后，紧跟加密的 ICMP 数据面。对照 [5.3 节](../05_wire_format/5.3_control_plane_frames.md)与[5.4 节](../05_wire_format/5.4_data_plane_frames.md)的逐帧解析，每一个字节都能对上。

### 10.1.4 改常量，看断言

实验室最有趣的玩法是"搞破坏"：在 `make test` 的测试里改掉任何一个常量——密钥、PN 或 AAD——然后看哪条断言先挂。

```bash
make test 2>&1 | grep -A3 FAIL
```

挂掉的顺序就是概念重要性的顺序：先挂的是密码学根基（ICV/SAK unwrap），后挂的是组装细节。把常量改回去，绿色回归，说明你已经知道每个字段在密码学里承担的角色。
